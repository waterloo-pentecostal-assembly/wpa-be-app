## Collection: `challenge_groups`

Small groups of members who go through a Bible series together and encourage each other. **The document id is the group's join code**: 6 characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no `0`/`O`/`1`/`I`), generated by the app (`generateGroupCode`, `Random.secure()`). Creating a group picks a code and writes the group in a transaction that checks the id is unused (up to 5 attempts).

A group has at most **20 people, counting pending invites** (`kMaxChallengeGroupMembers`). Group names are trimmed, 1–40 characters.

Members and invites are stored twice: as **id arrays** (`member_ids`, `invited_ids`) for `array-contains` queries and security rules, and as **maps keyed by user id** (`members`, `invites`) holding each person's name and avatar, so the group screen needs no extra reads. A map entry whose id is not in the matching array is ignored.

| Field | Description |
|----|----|
| `name` *(string)* | Group name. Required |
| `description` *(string)* | Optional description, trimmed, up to 200 characters (`''` when none). Missing on older groups (reads as `''`) |
| `is_public` *(bool)* | Public groups are listed in "Find a group" and anyone can join them. Missing reads as `false` (private) |
| `search_tokens` *(array of strings)* | **Written by the backend** from `name` + `description` (see [Search tokens](#search-tokens)). Clients can't write it |
| `created_by` *(string)* | uid of the creator |
| `owner_ids` *(array of strings)* | uids of the owners (all members). The creator is the first owner. A group with members always has at least one owner. Missing on older groups: their creator is the owner until `owner_ids` is first written |
| `created_at` *(timestamp)* | Server timestamp |
| `member_ids` *(array of strings)* | uids of the members |
| `members` *(map)* | `{<uid>: {first_name, last_name, thumbnail, joined_at}}`. `thumbnail` is the member's `gs://` avatar thumbnail or `null`; `joined_at` a server timestamp |
| `invited_ids` *(array of strings)* | uids with a pending invite |
| `invites` *(map)* | `{<uid>: {first_name, last_name, thumbnail, invited_by, invited_by_name, invited_at}}`. `invited_by` is the inviting member's uid, `invited_by_name` their full name at the time |

Example:

```json
{
  "name": "Morning Readers",
  "description": "We read before work",
  "is_public": true,
  "search_tokens": ["be", "bef", "befo", "befor", "before", "mo", "mor", "…"],
  "created_by": "uidA",
  "owner_ids": ["uidA"],
  "created_at": "<timestamp>",
  "member_ids": ["uidA", "uidB"],
  "members": {
    "uidA": {"first_name": "Ada", "last_name": "L", "thumbnail": "gs://…/image_200x200.jpg", "joined_at": "<timestamp>"},
    "uidB": {"first_name": "Grace", "last_name": "H", "thumbnail": null, "joined_at": "<timestamp>"}
  },
  "invited_ids": ["uidC"],
  "invites": {
    "uidC": {"first_name": "Alan", "last_name": "T", "thumbnail": null, "invited_by": "uidA", "invited_by_name": "Ada L", "invited_at": "<timestamp>"}
  }
}
```

### How the app writes it

Every change except creation is a transaction that reads the group first (`ChallengeGroupsRepository`):

| Action | Who | Change |
|---|---|---|
| Create | anyone | new document with name, description, visibility and search tokens; the creator is the only member |
| Edit | an owner | `name`, `description`, `is_public`, `search_tokens` |
| Make owner | an owner | adds a member to `owner_ids` (written in full, so older groups get the field) |
| Remove member | an owner | removes one non-owner from `member_ids`/`members` |
| Invite | a member | adds uids to `invited_ids` + `invites.<uid>` (skips members and people already invited; fails if members + invites would exceed 20) |
| Accept invite | the invitee | moves themselves from `invited_ids`/`invites` to `member_ids`/`members` (fails if 20 members) |
| Decline invite | the invitee | removes themselves from `invited_ids`/`invites` |
| Join with code / join a public group | anyone with the code, or anyone for a public group | adds themselves to `member_ids`/`members`, removing their invite if any (fails if members + other invites reach 20) |
| Leave | a member | removes themselves from `member_ids`/`members`; **the last member leaving deletes the document** (pending invites go with it). An owner is also removed from `owner_ids`; **the last owner must name another member**, who is added to `owner_ids` in the same write |
| Delete | an owner, or an admin | deletes the document (owners: their group, from the group screen; admins: moderating public groups). Pending invites go with it |

Reads:
- **My groups:** `where('member_ids', arrayContains: uid)`, live, sorted by name in the app.
- **My invites:** `where('invited_ids', arrayContains: uid)`, live, newest invite first.
- **One group:** document get / snapshot (the group screen, join with code, invite screen).
- **Find a group, browsing:** `where('is_public', isEqualTo: true).orderBy('created_at', descending: true).limit(30)`.
- **Find a group, searching:** a [token search](#search-tokens) among `where('is_public', isEqualTo: true)`, sorted by name, at most 30.

My groups and my invites use Firestore's automatic single-field indexes. The two Find a group queries need composite indexes (see [`firestore_rules.md`](firestore_rules.md#indexes)).

## Search tokens

Every search in the app (people search, Find a group) works the same way, because Firestore has no case-insensitive or substring queries:

- Each searchable document has **`search_tokens`**: every prefix of 2–15 characters of every lower-cased word of its searchable text, sorted, without duplicates. `"Night Owls"` → `["ni", "nig", "nigh", "night", "ow", "owl", "owls"]`.
  - `users/{uid}`: from `first_name + ' ' + last_name`.
  - `challenge_groups/{code}`: from `name + ' ' + description`.
- **The backend writes them** (see [section 4](#4-functions-keep-search_tokens-up-to-date)); the app never does, and the rules don't let clients.
- A query is split the same way into words of 2+ characters (one-letter words are ignored, longer words cut to 15). A document matches when its tokens contain **every** query word, so each word matches the start of a word, in any order: `"jones mar"` finds "Mary Ann Smith-Jones"; a fragment from the middle of a word (`"ones"`) doesn't.
- Firestore allows one `array-contains` per query, so the app (`tokenSearch`) filters on the longest query word, fetches at most 50 documents, keeps those containing the other words too, and sorts by name.
- Tokenizer in the app: `domain/common/search.dart` (`searchTokens`, `searchQueryTokens`). The backend must produce identical tokens.

## People search over `users`

Inviting people searches the existing `users` collection with a token search among `where('is_verified', isEqualTo: true)`, leaving out the signed-in user, at most 20 results. Results use only `first_name`, `last_name` (trimmed) and `thumbnail`. Composite index: `is_verified` + `search_tokens` (array-contains); see [`firestore_rules.md`](firestore_rules.md#indexes).

- Users without `search_tokens` (until the function runs or the backfill is done) don't appear. They can still join with a code.
- Unverified users never appear.
- **Privacy:** Firestore rules apply to whole documents, so verified users can read every field of other verified users' documents, including `email`, `is_admin` and `reports`. Subcollections (`devices`, `notification_settings`) stay private.

## Field read: `achievements/{uid}.series_progress` of other users

The group screen streams `achievements/{uid}` for **every member** to show their progress (0–100, written by the `updateProgress` function) against the current series' target. A member whose document can't be read shows "Progress unavailable"; the screen still works.

## Backend changes needed (wpa-be-firebase)

### 1. Security rules and indexes

The complete updated rules file, and the composite indexes for people search, are in [`firestore_rules.md`](firestore_rules.md). In short:

- `challenge_groups/{groupId}`: `get` for any signed-in user (join code lookup); `list` for queries on your own groups / invites and on public groups; create with yourself as the only member; updates are an owner editing the details, making a member an owner or removing a non-owner; a member adding invites; or a person moving only their own entry (accept, decline, join, leave; the last owner must name the next owner), never over 20 seats; delete by an owner (`request.auth.uid in resource.data.owner_ids`, or `resource.data.created_by` on older groups without `owner_ids`), the last member, or an admin.
- `users/{userId}`: verified users can `get` / `list` other verified users' documents (people search). Users already write their own document, which covers the search fields.
- `achievements/{userId}`: readable by every signed-in user (was: own document only).

Firestore rules can't check that the reader shares a group with the achievements owner (the path has no group id), so the achievements rule opens `series_progress` to every signed-in user. If that is not acceptable, the alternative is to copy `series_progress` into each group's `members.<uid>` from `updateProgress`, and change the app to read it from there.

### 2. Callable function `nudgeChallengeGroupMember`

Called with `FirebaseFunctions.httpsCallable('nudgeChallengeGroupMember').call({groupId, memberId})`. Suggested behaviour:

- Reject unauthenticated callers (`unauthenticated`).
- Read `challenge_groups/{groupId}`; both the caller and `memberId` must be in `member_ids`, and they must differ (`permission-denied` / `not-found` / `failed-precondition`).
- Rate limit per caller → member (e.g. once a day). On a repeat, throw `resource-exhausted`; the app shows "You nudged them recently. Try again later."
- Send to the member's device tokens a notification such as "<Caller first name> nudged you" / "Keep going with <series title> — your group <name> is cheering you on!", with data `{notificationType: 'challengeGroupNudge', groupId}`. Tapping it opens the group.
- Any other error code is shown as "Unable to send nudge".

### 3. Optional: invite notifications

A trigger on `challenge_groups/{groupId}` updates can notify uids newly added to `invited_ids`, with data `{notificationType: 'challengeGroupInvite', groupId}`. Tapping it opens the Community tab, which lists the invite.

Consider a notification setting for nudges/invites: the app's notification settings document has no field for them yet, and `getOptedInDeviceTokens` treats a missing field as opted out.

### 4. Functions: keep `search_tokens` up to date

Both searches depend on `search_tokens` (see [Search tokens](#search-tokens)). The backend needs:

- **two triggers**: `updateUserSearchTokens` on `users/{uid}` (from `first_name` and `last_name`) and `updateGroupSearchTokens` on `challenge_groups/{groupId}` (from `name` and `description`);
- **a one-time backfill** over both collections;
- **the composite indexes** listed in [`firestore_rules.md`](firestore_rules.md#indexes).

The full implementation spec is [`docs/specs/search-tokens-functions.md`](../specs/search-tokens-functions.md). It covers the exact algorithm, test vectors generated from the app's tokenizer, loop prevention and handling of out-of-order events, the backfill, and acceptance criteria.

- Until the backfill runs, existing users can't be found. Older groups are private anyway and only appear in Find a group once made public.
- A new or renamed public group shows in Find a group's **browse** list immediately, and in **search** once the trigger has run (usually within a second or two).
